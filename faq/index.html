Forkalope / FAQ

Start with the
hard questions.

Forkalope is early, so the honest answer is often a boundary: what the source can do, what the network is designed to do, and what still needs to be proven.

Nine answers · updated September 2026

What is Forkalope?

Forkalope is an open-source, GitHub-shaped code forge: repositories, issues, pull requests, automation, packages, permissions, and APIs in a familiar workflow. The larger idea is a cloud of independently operated nodes that can share authorized replicas and help one another recover when a primary home is unavailable. The forge comes first; the network has to earn its place through working software and tested operations.

Is this just another Forgejo or Gitea host?

Forgejo, Gitea, GitLab, and other projects already prove that self-hosted Git can work. Forkalope is exploring the layer they do not make central: portable identity and collaboration data, a visible relationship between node operators, and recovery between approved homes. That is a technical thesis, not a claim that Forkalope is more mature today.

Can I run Forkalope today?

The source and product direction are public, but the complete forge and shared recovery network are still in development. The current public build is this website. Follow the source repository for the first runnable slices, release notes, and the point at which a real demo is available. Until then, the site should not imply that a production forge or failover service already exists.

Does every node become part of production?

No. The planned network separates community nodes for mirrors, experiments, and learning; verified or anchor nodes that meet published checks for uptime, storage, backups, monitoring, and current software; and Forkalope core nodes operated for managed customers. A Raspberry Pi or home server can belong to the network without becoming a dependency for Acme’s production repositories.

What happens when a node crashes?

An approved recovery partner would use an authorized replica and reserved capacity to restore service while the original operator repairs or rebuilds the failed node. A real recovery system must account for more than Git objects: permissions, issues, pull requests, packages, routing, authentication, and the latest confirmed write all matter. Forkalope should measure restore time and possible data loss in drills before offering automatic failover or an uptime guarantee.

What does a Co-Sysop membership pay for?

A Tine is a proposed $30 monthly unit that helps fund shared servers, storage, backups, bandwidth, monitoring, and the people keeping the network healthy. It gives you a visible stewardship relationship to a logical node. Forkalope or an approved operator keeps the provider account and administrative keys, and sponsorship does not grant access to private customer data.

What is different about $30, $60, and $90?

One Tine associates you with a node and its operator discussions. Two Tines support more capacity and give earlier access to network-building tools. Three Tines make you eligible to become the primary named steward of a logical node; that node can move from one server or provider to another while the stewardship relationship follows it. None of the tiers buys a physical server, equity, or a share of business revenue.

What is an Independent Sysop?

An Independent Sysop rents infrastructure in their own name, runs Forkalope, and takes responsibility for security, updates, capacity, backups, and incidents. An approved Sysop can coordinate Co-Sysops and participate in recovery under a separate operator agreement. This is an operating role with real duties, not a fourth membership tier or a reward for recruiting members.

Why would a business switch?

Git repositories are already exceptionally portable: a company can mirror the commits and push them elsewhere. The expensive part of moving is the surrounding forge state accumulated over years—issues, pull requests, reviews, comments, labels, milestones, teams, permissions, branch protections, rulesets, Actions environments and secrets, runner configuration, packages, release artifacts, audit and security data, webhooks, apps, SSO mappings, and links in other tools. GitHub provides export and migration tooling, but that work still requires archives, APIs, validation, and sometimes downtime. Forkalope’s stronger goal is to make the complete development home portable: export everything in documented formats, or move the same Forkalope deployment to infrastructure your company controls. Switching hosting providers should not require switching platforms.
